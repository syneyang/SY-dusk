# 数据格式

两种导出，两种用途，都只依赖纯文本。

## 1. JSON 备份（完整、可导回）

文件名：`朝夕备份-2027-01-01.json`

```json
{
  "app" : "com.syneyang.dusk",
  "entries" : [
    {
      "createdAt" : "2027-01-01T14:32:00Z",
      "day" : {
        "day" : 1,
        "month" : 1,
        "year" : 2027
      },
      "id" : "11111111-2222-3333-4444-555555555555",
      "isPinned" : false,
      "mood" : "good",
      "tags" : [
        "旅行"
      ],
      "text" : "今天去了海边。\n风很大。",
      "title" : "海边",
      "updatedAt" : "2027-01-01T14:40:00Z"
    }
  ],
  "exportedAt" : "2027-12-31T15:00:00Z",
  "version" : 1
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | Int | 格式版本，目前是 1 |
| `app` | String | 固定 `com.syneyang.dusk` |
| `exportedAt` | ISO 8601 | 导出时刻 |
| `entries[].day` | `{year, month, day}` | 这篇属于哪一天，全库唯一 |
| `entries[].text` | String | 正文，`\n` 换行 |
| `entries[].title` | String | 小标题，可为空 |
| `entries[].mood` | String? | `great` / `good` / `calm` / `tired` / `low` |
| `entries[].tags` | [String] | 标签，不带 `#` |
| `entries[].isPinned` | Bool | 是否置顶 |
| `entries[].createdAt` / `updatedAt` | ISO 8601 | 创建 / 最后修改时刻 |

导入规则：**按天合并**。同一天如果两边都有，保留 `updatedAt` 更晚的那一篇；不会产生重复条目。

## 2. Markdown（给人读、给别的软件读）

按年一份，文件名：`朝夕-2027年.md`

```markdown
# 2027 年 · 朝夕

> 128 篇 · 120 天 · 约 46800 字

## 一月

### 1月1日 周五 · 不错

**海边**

#旅行

今天去了海边。
风很大。

---

### 1月2日 周六

……

---
```

规则：

- 一级标题：`# 2027 年 · 朝夕`
- 引用块：这一年的篇数、天数、字数
- 二级标题：中文月份
- 三级标题：`月日 周几`，有心情时追加 `· 心情`
- 标签行：`#标签1 #标签2`
- 每篇之间用 `---` 分隔
- 空日记在正文位置写 `（没有正文）`
- 置顶的日记标题里带 📌

全部导出（`朝夕-全部日记.md`）的结构相同，只是把每年放在 `## 2027 年` 这样的二级标题下。

## 3. 为什么用这两种

- JSON 负责**完整**：字段一个不少，能原样导回，是真正的备份。
- Markdown 负责**长久**：十年后任何编辑器都打得开，不依赖这个 App 还在不在。
